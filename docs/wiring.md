# How it is wired

The captain's life archive: every message, call, hangout and LLM session from his apps (Messenger, Instagram, WhatsApp, iMessage and SMS, the phone's calls, WeChat, X, Signal, Discord, Telegram, and his conversations with agents: Claude Code and his Grok Bot bots), kept in SQLite databases in one folder on this Mac, with everyone in them as people he names, tags and joins, and his inspirations: the things he saves for the ideas in them, by what they are about (see features.md's "Inspirations"). This project is the archive's code: the core (the agents' sessions and the event index, the calendar, the connectors' host, the change log and its undo, the backups, the trail of content reads, the CLI `npm run archive` and the server that answers for it) and its modules under `modules/` (see features.md's "Modules"). The friend map module (`modules/friend-map/`, its README) is the social layer: the message archive, the chat connectors that import each platform's exports and keep the live ones in sync, people and the rules that join and archive them, and friend-map's page.

friend-map's page, once friend-map-frontend's (`~/Projects/friend-map-frontend`, now retired), is the friend map module's own code (`modules/friend-map/page/`, see "What came from friend-map") and is served by this project's own server under `/friend-map/`: its map, Table, Calendar and person panel read and edit the archive at `/friend-map/api/archive/` (the same contract the server answers at `/api/archive/`), and its own scoring (closeness, the activity chart) is worked out by the page's own code over the facts the archive gives (`modules/friend-map/server/page/scoring.ts`). So in these documents "the app" and "the page" are friend-map's page, and a path under `src/` that is not in this repository (a `.tsx` file, `src/demos/`) is the page's, in `modules/friend-map/page/src/`. The archive also has a viewer of its own at `/life-archive/` (see console.md's "The viewer"): a table and a volume-over-time chart for each kind of event, calls first.

## Architecture

The system and its policy are written down in `docs/`, not drawn in the viewer (the console's Architecture page was removed on 2 November 2026; each platform's status and settings are read in Events > Sources):

- `docs/architecture.md`: the whole system, the archive and friend-map, part by part: what each part is, its files and tables, what feeds what, every route of the archive's server, and a note for every table and column. It was written from the removed page's map and nothing checks it against the code: correct it as you go.
- `docs/platforms.md`: for each chat platform, each connector that reads it, with how its messages arrive (live, from an app's database on this Mac, from an iPhone backup, or as an export the platform makes when asked), how its calls arrive and whether they say how long they were, how it treats end-to-end-encrypted chats, and how it keeps up. It is written from the connector manifests (`modules/friend-map/server/platformsDoc.ts`, from `server/connectors/manifests.ts`): the way and the step to get a fresh copy, which `import-status` and `docs/import-runbook.md` go by too, and each manifest's `calls` and `encrypted`, which every connector must state.
- `docs/privacy.md`: the privacy policy in its three layers: content (message text, media, the captain's hangout notes and drafts, and every copy that holds them), read only when he asks, every read logged, and by default other people's messages by local models alone; metadata (names, times, durations, counts and the rest of the index), which they read freely; and the repository, what may be committed or published, with the few kinds that stop a commit and what is fine, said outright: friend-map's, and apart a public fork's. The policy itself is `server/privacy/policy.ts`, the one place it is written, and AGENTS.md points to it: `PRIVACY` holds the first two layers, and `REPO_PRIVACY` and `FORK_PRIVACY`, apart, the third, which are the privacy guard's policies (its model review is given each as written).

`npm run docs` (`tools/docs/docs.ts`) writes `docs/platforms.md` and `docs/privacy.md` from the code, and `tools/docs/docs.test.ts` fails while either is not what it would write: change the manifest or the policy, run the command, and commit both.

## What came from friend-map

friend-map-frontend is retired: the captain is folding it, with the rituals repository, into this project ("We're essentially folding everything into this live archive modularization objective"). Its own server (`local.friend-map`) is no longer the way to the archive. What this project took of it is its own now, changed here like any other code:

- **friend-map's page**, `modules/friend-map/page/`: its `index.html` and every file it reaches, brought in from friend-map-frontend's commit 45ec3e6 (only what the page served here needs: not friend-map-frontend's own server, its demo build, its tests or its docs). Four of its files are over the 1000-line cap and on the ratchet (`oversized-files.json`) as they came. It still links to friend-map's public demo (friend-map-demo.pages.dev) and has a Demo entry, left until the captain decides whether the public demo stays.
- **The contract**, `src/archive.ts`: the shapes the archive's `/api/archive` answers and the page renders and writes back. One copy: the module's server half imports it through the SDK, and the page through its own `src/archive.ts`, which re-exports `sdk/contract.ts` (the module page's Vite serves the core's `sdk/` and `src/` to it for that).
- **The made-up names**, `server/fixtures/madeUpNames.ts`: the names every test takes its names from.
- **The page's copies.** The page keeps its own copies of the archive's name check (`isPlaceholderName` in `page/src/names.ts`) and query language (`page/src/demo/query.ts`), so its demo mode needs none of the server's code. `modules/friend-map/server/pageCopies.test.ts` checks them case by case against the archive's. (friend-map-frontend's demo parity test, which ran its demo generator and in-page archive beside a real archive, went with it: that demo was never part of the page served here.)
- **The helpers copied once**, each side's own from then on: `src/time.ts` (local days and months), `identicon.ts` (a person's identicon seed), `groupName.ts` (how many people an untitled group is named by), `calls.ts`, `catchUps.ts`, `eventWords.ts`, and `server/errors.ts`, `files.ts`, `jsonApi.ts`, `allowedHosts.ts`, `nodeVersion.ts`, `onPinnedNode.ts` and `dataHome.ts`. The page has its own older copies of some of them, which have drifted.
- **The privacy guard.** friend-map-frontend's guard policy, the privacy policy's repository layer (`REPO_PRIVACY`; see guard.md's "The privacy guard"), became the `life-archive` policy when that repository was archived (7 November 2026); the guard no longer checks friend-map-frontend's commits.
